01 · Learning objectives

What this lab covers

The Day 1 lab in the GitHub repository focuses on foundational Linux operations:

  • Develop fluency with the shell and filesystem.
  • Inspect processes and understand basic permissions and ownership.
  • Work with environment variables, pipes, and redirection.
  • Build the habits needed to troubleshoot containers, servers, and Kubernetes workloads.

03 · Engineering significance

Why this matters for AI infrastructure

Most ML infrastructure ultimately runs on Linux. If a model server stops responding or a container fails to start, investigation often begins with process state, permissions, files, and logs. These fundamentals become increasingly important in GPU infrastructure and Kubernetes operations.

Interview takeaway

Establish the current system state before changing anything: inspect processes, resources, files, permissions, and logs, then narrow the problem to the relevant layer.

05 · Reflection

Think like an operator

When a Linux application behaves unexpectedly, what would you inspect first? The strongest first response is to gather evidence without making assumptions: process health, logs, filesystem access, resource pressure, and configuration.

This approach carries forward to the later GPU scheduling, inference, and troubleshooting labs.
