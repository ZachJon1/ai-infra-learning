Networking is a stack of layers

Each layer hands the packet to the one below it on the way out, and back up on the way in.

When something breaks, check one layer at a time instead of guessing.

Your host has several doors to the network

Each network interface is a way in or out, and each holds its own IP. Loopback, lo, is special: 127.0.0.1 means “this machine,” so its traffic never leaves home.

ip addrip linkhostname -I

Switched on isn’t the same as plugged in

UP means the OS enabled the interface. LOWER_UP means the link actually works. No cable gives NO-CARRIER and state DOWN, even with UP set.

ip link

An IPv4 address is 32 bits in four boxes

Each box holds 8 bits, so it ranges from 0 to 255. Addresses belong to interfaces, which is why one host can have several at once.

Private ranges are gated neighborhoods

These three blocks are set aside for internal networks. Homes, offices, clouds and containers reuse them freely.

The slash splits network from host

In 192.168.1.91/24, the first 24 bits name the network and the last 8 pick one host inside it.

Slash means network prefix. Colon means port.

Bigger prefix, smaller network

Every bit you lock for the network halves the room left for hosts. Drag the slider and watch the count change.

/24

MTU is the biggest box that fits

MTU is the largest packet an interface sends without splitting it, often 1500 bytes on Ethernet and Wi‑Fi. Across a whole path, the narrowest link sets the Path MTU.

Small requests work but big transfers stall? Suspect an MTU mismatch, common with VPNs, container overlays and GPU clusters.

The routing table is a signpost

An IP says where a packet is going; the routing table says how to get there. Linux picks the most specific matching route, and everything else goes to the default gateway.

ip routeip route get 8.8.8.8

Every packet carries a hop budget

Each router lowers the TTL by one. At zero the packet is dropped, so a routing loop can’t trap it forever.

tracepath 8.8.8.8

No reply from a hop doesn’t mean it’s down. Some routers forward traffic but ignore diagnostic probes.

IP is the building. Port is the apartment.

The IP gets traffic to the right host; the port picks which program receives it. A program waiting at a port is listening.

ss -ltnpsudo ss -tulnp

-t TCP -u UDP -l listening -n numbers -p process

Which doors does the server answer?

Binding decides which local addresses a server listens on. Same port, very different reach.

Binding to 0.0.0.0 is not a firewall rule.

One receptionist, many desks

A socket is a kernel-managed endpoint, and a process holds it by a small number called a file descriptor. The listening socket keeps greeting; every accepted client gets its own connected socket.

users:(("python3",pid=62540,fd=3))

Three ways to talk

TCP sets up a reliable, ordered conversation with a three-way handshake. UDP just sends datagrams. ICMP carries control and diagnostic messages, like ping.

Clients get temporary ports too

Linux hands each client a short-lived ephemeral port. Four values (source IP, source port, destination IP, destination port) tell every TCP connection apart.

DNS turns names into addresses

Apps ask a local stub resolver at 127.0.0.53, which is why /etc/resolv.conf often lists it. On a cache miss it asks upstream, then remembers the answer.

resolvectl query example.comresolvectl statusgetent hosts example.com

IP works but the hostname fails? Suspect DNS first.

The firewall is the bouncer

A service can be running, listening on 0.0.0.0:8000 and correctly routed, and still be blocked by a firewall rule.

sudo ufw status verbose

Troubleshoot from the bottom up

Confirm each layer before you climb to the next. Every rung you clear rules out a whole category of failure.

Nothing listening on port 8000? DNS isn’t your problem yet.

Myth busting

Seven ideas that trip people up, and what’s actually true.

  • myth0.0.0.0 means open to everyoneIt means listen on all local IPv4 interfaces. Firewalls and routing still control who can reach it.
  • myth/24 is a portA slash starts a CIDR prefix. A colon starts a port.
  • mythPing proves a web service worksPing tests ICMP reachability, not TCP or HTTP.
  • mythOne port can only serve one clientOne listener accepts many connections, each told apart by its endpoints and ports.
  • mythNo trace reply means the router is downIt may forward traffic while ignoring diagnostic probes.
  • mythThe default gateway is “the Internet”It’s the next-hop router used when no more-specific route matches.
  • mythAn IP belongs to the whole computerIP addresses are assigned to interfaces, so one host can have several.

Check your understanding

Answer each one in your head, then tap to check. Autoplay waits here; press next when you’re ready.

  1. Why can 127.0.0.1:8000 work while 192.168.1.91:8000 fails on the same host?

    The server is bound only to loopback (127.0.0.1), so it isn’t listening on the Wi‑Fi address at all.

  2. What does 192.168.1.91/24 tell you that 192.168.1.91:8000 doesn’t?

    The network prefix: this interface lives in the 192.168.1.0/24 network. The colon version names a port instead.

  3. ping 8.8.8.8 works but resolvectl query example.com fails. What do you investigate first?

    DNS, meaning name resolution. IP connectivity is already proven, so the name lookup is the strongest suspect.

  4. How can 100 clients connect to one server on TCP port 8000 without 100 server ports?

    Each connection has a unique 4-tuple. Clients use different ephemeral source ports, and accept() gives each one its own connected socket.

  5. ss -ltnp | grep 8000 returns nothing. Why check the app before the firewall?

    Nothing is listening, which is a lower layer than the firewall. No firewall rule can make a missing listener answer.

You can trace a request end to end

Name to address, route to gateway, handshake to HTTP. When something breaks, climb in order: process, socket, binding, interface, route, connectivity, firewall, DNS, then the app.
