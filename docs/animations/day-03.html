Signals: tiny notes for processes

The kernel slips a short message to a process. Most can be handled by the program. Two cannot.

PID 24531
1SIGHUP

Hang up: the terminal went away. Often reused for “reload config”.

2SIGINT

Interrupt. What Ctrl+C sends.

9SIGKILL

Forced stop by the kernel, right now.

🔒
15SIGTERM

“Please finish up and exit.” The polite one.

18SIGCONT

Carry on. Unpauses a stopped process.

19SIGSTOP

Freeze, immediately.

🔒
20SIGTSTP

Pause from Ctrl+Z. Programs may handle it. (Usually 20.)

🔒 means it can’t be caught or ignored. The program gets no say.

kill doesn’t always mean kill

It really means “send a signal”. With no option, the signal is SIGTERM.

kill 24531 kill -15 24531 kill -TERM 24531
SIGTERM 15All three send the same note.
kill -9 24531⟶SIGKILLforced stop, no cleanup
kill -STOP 24531⟶SIGSTOPfreeze it
kill -CONT 24531⟶SIGCONTunfreeze it

A polite knock vs. a bulldozer

SIGTERMkill PID
train.py
👋
  1. Stop taking new work
  2. Save a checkpoint
  3. Flush logs and files
  4. Exit cleanly
SIGKILLkill -9 PID
train.py
💥
  • No checkpoint saved
  • Buffered data lost
  • Other workers never told

The kernel still frees its memory and open files.

Rule: send SIGTERM first. Reach for SIGKILL only when the process won’t stop.

Why did my training stop overnight?

A background job still belongs to the shell that started it.

Plain &python train.py &
💻 Laptop ⚡ SSH shell SIGHUP

The connection drops, the shell exits, its jobs get SIGHUP, and training ends.

With nohupnohup python train.py &
💻 Laptop ⚡ SSH shell SIGHUP nohup

The hangup bounces off. Training keeps going.

Myth busters

Myth

“kill always kills.”

“kill always kills.”

kill sends a signal. The default is SIGTERM, a polite request.

Myth

“& detaches a job.”

“& detaches a job.”

It only backgrounds it. A hangup can still reach it.

Myth

“A zombie is stuck running.”

“A zombie is stuck running.”

It already exited. Its parent just hasn’t reaped it.

Myth

“Children always die with their parent.”

“Children always die with their parent.”

Not guaranteed. Orphans keep running and get adopted.

Myth

“High VRAM means the GPU is busy.”

“High VRAM means the GPU is busy.”

Memory allocation and compute use are separate numbers.

Myth

“State D means the GPU is broken.”

“State D means the GPU is broken.”

Usually it’s kernel-level waiting on storage or network I/O.
